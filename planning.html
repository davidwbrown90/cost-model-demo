How this plan works

Plan at purchase-order level

Each PO (or contract, asset or payroll line) has its own FY2027 plan. Vendors and accounts are just the totals of the POs beneath them, so any number can be drilled back to the PO that caused it.

How a PO's plan is set

Run-rate: the last three months of actuals, plus an uplift %. Same as last year: each month of FY26 outturn, plus an uplift. Manual: typed in (editing an annual figure or a month does this). Stop: run-rate until a month you choose. New: a PO that does not exist yet.

Contracts that end

If a contract ends before the plan year does, someone has to decide: Renew keeps it going, Lapse stops it at the end date. Until you decide it is assumed to continue, so the plan is not understated, and it is flagged.

Top-down and bottom-up

Each account has a target. The gap column is plan minus target. Allocate target overwrites the account's POs so they add up to the target exactly, sharing it by last year's spend. Undo reverses it.

FY26 outturn

Actuals for January to September plus the forecast for October to December. The FY26 budget is shown for reference. Everything here is fictional.

Where changes are kept

Edits are saved in this browser only (nothing is sent anywhere). Reset returns to the starting plan, and Export CSV downloads the plan at PO level.

Where the plan lands: IT towers, applications and business units

The plan, line by line, is allocated through the same cost-model rules used for actuals (ledger to IT towers to applications to business units). Change a PO above and this recalculates. FY26 outturn is run through the same rules for comparison.

Plan a new PO

Spend you expect next year that has no purchase order yet. It joins the plan straight away and can be removed again.
